# Hands-On Hashing with CyberChef

Bitcoin နဲ့ Crypto အကြောင်း လေ့လာရင်း **SHA-1, SHA-256, Hashing** ဆိုတဲ့ စကားလုံးတွေ မကြာခဏတွေ့လာပါတယ်။ စာနဲ့ပဲ ဖတ်နေရင် တစ်ခါတလေ နားလည်ရခက်တာကြောင့် ဒီတစ်ခါတော့ **ကိုယ်တိုင် လက်တွေ့စမ်းကြည့်ရအောင်** လို့ စဉ်းစားမိပါတယ်။

Programming သိစရာမလိုပါဘူး။ Hash စမ်းကြည့်ဖို့ **CyberChef** ကို အသုံးပြုလို့ရပါတယ်။

[CyberChef – Hashing Tool](https://gchq.github.io/CyberChef/)

### Exercise 1 - စာတစ်ကြောင်းကို Hash လုပ်ကြည့်မယ်

CyberChef ထဲမှာ **SHA2 (256)** Operation ကို ရွေးပြီး အောက်ကစာကို ထည့်ကြည့်ပါ။

`hello world` ပြီးရင်... `Hello world`

လို့ **H တစ်လုံးကိုပဲ အကြီးစာလုံးပြောင်းပြီး** ထပ်စမ်းကြည့်ပါ။

### ဘာတွေ့ရလဲ?

စာက တစ်လုံးပဲ ပြောင်းသွားပေမယ့် Hash Output ကတော့ **လုံးဝမတူတော့တာ** တွေ့ရပါလိမ့်မယ်။ ဒါက Hashing ရဲ့ အရေးကြီးတဲ့ သဘောတရားတစ်ခုပါ။

> **Input နည်းနည်းပြောင်းတာနဲ့ Hash Output က လုံးဝပြောင်းသွားနိုင်တယ်။**

### Exercise 2 - Space တစ်ချက် ထည့်ကြည့်မယ်

အခု...

`hello world` နဲ့ `hello world `

ဒုတိယစာကြောင်းမှာ `world` နောက်မှာ **space တစ်ချက်** ပါပါတယ်။ နှစ်ခုလုံးကို SHA-256 Hash လုပ်ကြည့်ပါ။ Hash နှစ်ခု တူပါသလား?

**မတူပါဘူး။**

စာကြောင်းရဲ့ အဆုံးမှာ Space တစ်ချက်ပဲ ထည့်လိုက်တာနဲ့ Hash တစ်ခုလုံး ပြောင်းသွားတာကို တွေ့ရပါမယ်။

### Exercise 3 - Password ကို စမ်းကြည့်မယ်

အခု...

`password` နဲ့ `password1234`

ကို Hash လုပ်ကြည့်ပါ။ Hash Output တွေကို နှိုင်းယှဉ်ကြည့်ပါ။ ဒီနေရာမှာ အရေးကြီးတာတစ်ခုက... **Hash လုပ်ထားပြီဆိုတိုင်း Password လုံခြုံပြီလို့ မဆိုလိုပါဘူး။**

Password ကိုယ်တိုင်က `password`, `123456`, `password1234` လိုမျိုး **ခန့်မှန်းရလွယ်တဲ့ Password** ဖြစ်နေရင် Attacker က Guessing / Dictionary နည်းတွေနဲ့ စမ်းပြီး Hash နဲ့ တိုက်စစ်နိုင်ပါတယ်။

ဒါကြောင့်...

> **Hashing ≠ Password Security အပြည့်အဝ**

Password Storage မှာလည်း SHA-1 / SHA-256 ကို ရိုးရိုးအသုံးပြုရုံနဲ့ မလုံလောက်ပါဘူး။ သင့်တော်တဲ့ Password Hashing / KDF နည်းလမ်းတွေကို အသုံးပြုရပါတယ်။

### Exercise 4 - SHA-1 နဲ့ SHA-256 ကို နှိုင်းယှဉ်ကြည့်မယ်

တူညီတဲ့ Input တစ်ခုကို...

**SHA-1** နဲ့ **SHA-256**

နှစ်မျိုးလုံးနဲ့ Hash ထုတ်ကြည့်ပါ။ SHA-1 က **160 bits = 40 hexadecimal characters** SHA-256 က **256 bits = 64 hexadecimal characters** ရှိတာကို တွေ့ရပါမယ်။

ဒါပေမယ့် **Output ပိုရှည်တာတစ်ခုတည်းနဲ့ Security ပိုကောင်းတယ်လို့ မဆုံးဖြတ်သင့်ပါဘူး။** SHA-1 ဟာ ယနေ့ခေတ် Security Design အသစ်တွေအတွက် မသင့်တော့တဲ့ Hash Function ဖြစ်ပါတယ်။

### ဒီ Exercise ကနေ ဘာသိလာလဲ?

ကျွန်တော်အတွက်တော့ ဒီ Exercise ကနေ အဓိက နားလည်လာတာက... **Input → Hash Function → Hash Output** ဆိုတဲ့ Process ပါ။ ပြီးတော့...

- Input နည်းနည်းပြောင်း → Hash လုံးဝပြောင်း
- Hash Output ကနေ Original Input ကို ရိုးရိုး “Decrypt” လုပ်လို့မရ
- Weak Password ဖြစ်ရင် Guessing / Dictionary / Lookup နည်းတွေနဲ့ ရှာတွေ့နိုင်
- SHA-1 ဟာ Modern Security အတွက် မသင့်တော့
- SHA-256 ဟာ Bitcoin မှာ အရေးကြီးတဲ့နေရာတွေမှာ အသုံးပြုထားတယ် ဆိုတာတွေကို စာဖတ်တာထက် **ကိုယ်တိုင်လုပ်ကြည့်ပြီး ပိုမှတ်မိလာပါတယ်။**

ဒီ Exercise ကို လုပ်ကြည့်မယ့်သူတွေအနေနဲ့ ကိုယ့်ရဲ့ **တကယ့် Password / Private Key / Seed Phrase** တွေကို Generator ထဲမှာ ဘယ်တော့မှ မထည့်ပါနဲ့။

လေ့လာရေးအတွက် `hello world` လိုမျိုး **အတုစာသားတွေကိုပဲ အသုံးပြုကြပါ။**

ကျွန်တော်လည်း Crypto ကို လေ့လာရင်း သိလာတာတွေကို ကိုယ်တိုင်ပြန်စမ်းကြည့်ပြီး နားလည်အောင် လေ့လာနေပါတယ်။

**Knowledge Sharing အနေနဲ့ မျှဝေတာဖြစ်လို့ အမှားရှိခဲ့ရင်လည်း ပြင်ဆင်ပေးကြပါခင်ဗျာ။**
